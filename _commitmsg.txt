Audit execution: actually persist responses so saving works reliably

Three bugs caused auditors to lose work, leaving empty Draft audits:

1. The item detail dialog's "Save Response" button only closed the
   dialog and never called the server, so status/observation/risk
   stayed in local state and were lost on navigation. It now flushes
   all pending responses to the backend before closing (and stays open
   on failure so input isn't lost).

2. The 30s auto-save interval listed `saveMutation` (new identity every
   render) in its deps, so it was torn down and recreated on every
   keystroke/click and never fired. Removed it from the deps.

3. saveMutation had no onError, so save failures were silent. Added a
   destructive toast on error.
